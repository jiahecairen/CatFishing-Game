# SDD_v0.1 — 桌面小猫钓鱼 / 最小技术原型

**状态**：Draft / 待项目所有者审核后冻结（SDD-179、180）。**不代表已经开发或测试。**  
**负责人**：项目所有者。执行工具：DeepSeek Harness + 本地 Qwen Flash（单 Agent）。  
**主平台**：Godot 4.x、GDScript、Apple Silicon macOS；Windows 11 兼容性必须尽早探查。

## 1. 核心目标

仅验证：Godot 4 是否能作为轻量的**透明桌面小船+猫咪挂件**稳定工作，猫能在后台活动时**自动捕鱼**，渔获进入鱼篓，玩家可手动出售、增加金币，保存并恢复数据。v0.1 是技术原型，不是完整游戏，不要求正式猫咪形象和森林/船舱生活。

### 用户故事

- **U01**：我在 Mac 桌面上看到不遮挡背景的像素风小船与一只临时猫；我可以移动它并记住位置。
- **U02**：我正常工作时猫自动抛竿、等待、上钩、收竿、结算；无需我反复点击。
- **U03**：我可以查看鱼篓，满了会停止新增捕鱼；我能手动出售再继续。
- **U04**：重启应用后，金币、鱼篓、位置和必要运行状态不发生丢失/重复结算。
- **U05**：桌面使用不被覆盖式窗口、鼠标穿透错误、通知轰炸或高资源持续占用打扰。

### 其他明确前提

- 基础状态/UI 必须精简：满篓轻提示；保存失败持续可见提醒但不弹系统通知；用户全屏/勿扰时避免干扰。
- 默认展示临时像素猫与小船，美术锚点/逻辑像素规范可迭代，但**不要进行正式 AI 像素素材批量生产**。
- 不要把任何需要地图/NPC/世界场景才能运行的功能带入 v0.1。没有全游戏 UI 时用简单面板/菜单实现手动售鱼。
- `GameState` 为金额/鱼篓/事务状态唯一权威；UI 不得重算并擅自保存金额。

## 3. WON'T — v0.1 明确不做

- 角色创建器、永久猫咪名字/外形设定、复杂猫咪自主船舱生活、家具和房间、猫咪思想气泡、罕见动画池、动画收藏/图鉴。
- 森林/湖泊地图、NPC、剧情序章、手动钓鱼、全屏模式场景、造船厂、升级/装修、养成料理水族馆、任务、天气影响钓具属性。
- 联机、Steam Multiplayer、好友与聊天/表情、付费系统/DLC、多人存档同步。
- 正式离线产鱼收益（程序**完全退出**后产生 8h～24h 收益的设计属后续版本）；不得把窗口隐藏错误当成离线获得收益。
- 完整 Win11 发行验收、Steam 发布、8 人房间架构落地、云备份服务。

这些功能可能属于未来版本，**不代表取消长期目标**，详见 `PRODUCT_ROADMAP.md`。

## 4. v0.1 关键时序

1. 启动→验证配置→恢复有效存档（或创建干净初始状态）→初始化桌面窗口和临时视觉→显示当前捕鱼状态。
2. 若篮未满且保存状态可用→启动 `CASTING`→`WAITING`，由可注入 RNG 生成 20–60s 待咬钩时间。
3. 有效捕鱼时钟推进到随机时间→`HOOKED`→`REELING`→`SETTLEMENT`。仅成功提交唯一 catch ID 后将鱼实例放入篮并保存状态；重复重试不重复放鱼。
4. 若满篓→停在安全空闲状态，不开启新 `CASTING`；提示但不打扰。
5. 玩家手动出售→执行唯一 sale ID 的原子库存扣减+金币增加→成功保存后展示结果；成功出售腾出空间后可恢复下一次抛竿。
6. 保存失败→保留恢复依据和未确认状态，暂停新的经济事务并提示；不得显示未提交金币。
7. 应用退出/崩溃→恢复时核对交易 ID、提交状态；不重放已结算事件。

### 计时边界

“有效捕鱼时间”须与状态机定义明确：只有当前允许捕鱼的运行段计入等待；空闲/满篓/挂起/错误期间不得继续结算。**隐藏窗口与完全退出的区别已确定，隐藏期间实际是否继续计入有效等待**：应依照已确认的运行状态规则实现、保守不产生离线收益；若当前可恢复原始决策不足以判定隐藏期间应暂停还是继续等待，列为 `OPEN-001` 提请用户一次性确认，绝不能擅自发放收益。

## 5. 玩家交互 / 可观察性

- 移动：按下船/猫可交互区后开始拖动，设最小拖动阈值，释放后保存窗口位置；透明区需真实穿透测试。
- 简单信息：点击/右键入口展示三项最小数据（鱼篓占用、金币、捕鱼状态）和手动出售操作；具体 GUI 选择需结合 macOS 技术 spike，但不可修改经济规则。
- 全屏或手动隐藏：不弹系统通知、不挡其他 App；窗口穿透技术不可行时应提出受限降级方案并获用户批准，不得静默牺牲用户桌面交互。
- v0.1 可以采用临时 sprite/形状，固定 30 FPS，质量重于视觉复杂度。
