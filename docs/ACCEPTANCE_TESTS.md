# v0.1 验收标准与自动化测试方案

**原则：证据优先、可重复、失败阻断放行。** 正式验收须由用户在实际 Mac 上查看测试结果并批准。每张工单产生机器可读结果（建议 JSON）；看似正常的截图不可替代状态机/经济事务测试。

## 1. 测试分层

| 层级 | 执行方式 | 目标 |
|---|---|---|
| 静态/配置 | JSON 解析、GDScript lint/语法导入 | 非法数据拒绝、项目资源能加载 |
| 单元 | Godot headless + 可注入 Clock/RNG | FSM、随机区间、容量、金币、计算等 |
| 集成 | Godot headless + SaveService+故障注入 | 持久化、冲突、崩溃恢复、重复事务 |
| 桌面 GUI | macOS 真正窗口运行，人工记录 | 透明、穿透、拖动、Retina、全屏共存 |
| 模拟/统计 | 虚拟时间 + 多固定种子 | 1h/4h/8h 捕鱼、鱼篓满时间分布、价格/捕获占比 |
| 稳定性 | macOS 连续约 8h 候选实际运行 | 无泄漏增长、未处理异常、冻结、经济错误 |

## 2. P0 机器可测断言

- **T-FSM-01**：不合法状态转移被拒绝并可记录；合法状态顺序完整。
- **T-TIME-01**：随机等待每次落在 20–60s 配置区间；给定同 seed/时钟/配置可重现。
- **T-TIME-02**：30 FPS、15 FPS、120 FPS 的模拟渲染条件不改变捕获事件时间序列（逻辑时间相同）。
- **T-TIME-03**：暂停、满篓和存档错误不新增捕鱼事件；隐藏与应用终止/离线收入区分，不得无依据发放收益。
- **T-ECO-01**：10 格候选满篓后不可开启新 `CASTING`；售鱼完成可释放格子恢复。
- **T-ECO-02**：同一 catch event ID 重试 100 次，最终入篮至多 1 条。
- **T-ECO-03**：同一 sale event ID 重试 100 次，金币增加至多 1 次；被售实例不得重复存在。
- **T-ECO-04**：售鱼请求重复/不存在/越权 ID、负价格、容量冲突均有明确错误；金币不可负。
- **T-SAVE-01**：退出重启金币、鱼篓、已处理事务、窗口位置均一致。
- **T-SAVE-02**：在临时写入、重命名、状态发布之前注入崩溃/写入失败，最终只出现 **旧已提交状态或新完整状态**，不可出现半个出售交易。
- **T-SAVE-03**：未知未来版本/损坏存档不被悄悄覆盖；保留可检查的原件和恢复方案。
- **T-CONF-01**：重复 species ID、非正权重、负价格、上钩 min>max、无效 JSON 阻止经济系统启动。
- **T-UI-01**：保存失败时提示可见而不弹系统通知，未经成功持久化不可显示已确认收入。
- **T-LOG-01**：必要事件拥有 severity/event ID；不收集按键、屏幕、其他 App 内容，无自动网络上传。

## 3. GUI 手动验收

- **G-001**：macOS Finder/浏览器位于窗口后；透明位置点击由下方应用接收，猫/船交互区能响应。
- **G-002**：小船拖动、普通点击不会误判；位置重启恢复。
- **G-003**：Retina 缩放不产生明显错位或整块不透明矩形；主屏到外接显示器移动（若可测）。
- **G-004**：桌面可见时约 30 FPS（允许测量误差/后台系统调度），隐藏时停止不必要的帧绘制；不得以隐藏充当完全退出。
- **G-005**：满篮/保存失败信息不轰炸通知或阻碍其他 App。

## 4. SDD-178 多种子模拟

建议第一次使用至少 20 个不同固定随机种子（**测试工程建议值，并非已锁定 SDD 参数**），分别运行 1h/4h/8h 虚拟捕鱼流程，既模拟不售鱼直到满篓，也模拟售鱼后恢复。计算：

- 捕鱼完整周期 `CASTING+WAITING+HOOKED+REELING+SETTLEMENT`，平均/中位/P10/P90。
- 首次鱼篓满时间的均值/中位/P10/P90；若始终不满需显示原因。
- 3 鱼种的捕获数、占比、总价值及每次售出的金币。
- 已处理 catch/sale ID 重复计数 **必须 0**；满篓后新 cast **必须 0**。
- 保存失败故障注入后，状态恢复前的新增事务 **必须 0**。
- 提交给用户明确审核：是否调整鱼价/等待时长/候选容量。Agent 不得自动为了“平衡”修改参数。

机器报告参考格式：

```json
{
  "suite": "economy-simulation",
  "build_id": "unreleased-local",
  "seeds": [11, 13, 17],
  "virtual_hours": [1, 4, 8],
  "summary": {
    "basket_capacity": 10,
    "bite_wait_min_sec": 20,
    "bite_wait_max_sec": 60,
    "first_fill_seconds_p50": null,
    "species_counts": {},
    "duplicate_catch_transactions": 0,
    "duplicate_sale_transactions": 0,
    "casts_started_while_full": 0
  },
  "pass": false,
  "notes": ["EXAMPLE STRUCTURE ONLY — NOT AN EXECUTED TEST"]
}
```

## 5. 8 小时稳定性

- 在目标 Mac 上以正常可见桌面状态（并测试隐藏/再显示切换）运行累计至少候选 8h。记录开始/结束的 Godot、macOS、渲染器版本和内存/CPU/能耗趋势。
- 失败判据：崩溃、卡死、不可恢复保存故障、无限重试、重复结算、窗口无法恢复、持续异常资源增长。
- 资源数值阈值：**需真实测得基线后由用户确认**，不要任意写 1% CPU/100MB 内存等不可靠固定数字。

## 6. CI / 审核门禁

- 每张票至少 headless 能通过；平台 UI 票还需 GUI 证据。
- 集成失败阻断合并/发布；用户审查前不要自动把报告改成 `pass:true`。
- 新功能需要可回滚小提交；每次报告命令、退出码、日志位置、Git diff 与遗留风险。
- 不允许 Agent 擅改测试断言来让失败变成功。
